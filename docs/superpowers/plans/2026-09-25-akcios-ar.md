# Akciós ár – megvalósítási terv

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Az ERP-ben akciósnak jelölt termékeket a vevő akciós áron lássa (áthúzott eredeti ár + akciós ár + „-X%” címke), és a kosár, a pénztár és a rendelés akciós áron számoljon.

**Architecture:** Az üzleti szabály egyetlen helyen, a `Product` modell három számított attribútumában él (`effective_sale_percentage`, `sale_price`, `unit_price`). Minden vevőoldali összeg a `unit_price`-ból számol; a megjelenítést egy közös `<x-product-price>` Blade-komponens rajzolja.

**Tech Stack:** Laravel 13, Livewire 4, Pest 4, Tailwind 4, PHP 8.4.

**Spec:** `docs/superpowers/specs/2026-09-25-akcios-ar-design.md`

## Global Constraints

- Akciós: `is_on_sale = true`. Kedvezmény: akciós és `sale_percentage` 0/üres → **10%**; akciós és > 0 → az ERP-érték; nem akciós → 0.
- Akciós nettó egységár: `round(net_selling_price × (1 − kedvezmény / 100))` – egész forint.
- A szabály nincs mentve az adatbázisba (számított attribútum).
- Minden ár nettó; a „+ÁFA” megjelenítés változatlan.
- Pénzformátum a meglévő mintát követi: kártyán/termékoldalon/kosártételben `Number::currency($x, 'HUF', 'hu', 0)` (nem törő szóközzel: `1 234 Ft`), összesítőkben `number_format($x, 0, ',', ' ') . ' Ft'`.
- Minden PHP-változtatás után: `vendor/bin/pint --dirty`.
- **Push = éles deploy** (Forge auto-deploy). Feladatonként csak lokális commit; push a végén, a felhasználó jóváhagyásával.

## Review Focus

1. Akciós termék `net_selling_price = null` vagy 0 → nem lehet hiba, `sale_price` 0 vagy null, a kártya nem mutat áthúzott „0 Ft”-ot. (Teszt: Task 1.)
2. Akciós termék 100% (vagy > 100%) kedvezménnyel → az ár nem lehet negatív; 100%-nál 0 Ft. (Teszt: Task 1 – a kedvezményt 0–100 közé szorítjuk.)
3. A kosárban lévő termék akciója időközben megszűnik/változik → a kosár és a pénztár az aktuális `unit_price`-szal számol (élő érték, nem mentett). (Teszt: Task 2.)
4. Gyorskereső: a lekérdezés `select()`-je szűk oszloplistát kér → az `is_on_sale`/`sale_percentage` nélkül az akciós ár csendben elveszne. (Teszt: Task 3.)
5. Tizedes nettó ár (pl. 999.50) akcióval → a kerekítés egész forintra történik, a rendelési tétel részösszege = kerekített egységár × mennyiség. (Teszt: Task 1 és Task 2.)

`app/Models/Product.php` – az `isInStock()` után:

```php
    public function isOnSale(): bool
    {
        return (bool) $this->is_on_sale;
    }
```

Az `imageUrl()` attribútum után:

```php
    /**
     * Az érvényes kedvezmény százalékban. Akciós terméknél az ERP „Akció %”
     * értéke, vagy 10%, ha az 0 vagy üres; nem akciósnál 0. 0 és 100 közé szorítva.
     */
    protected function effectiveSalePercentage(): Attribute
    {
        return Attribute::get(function (): float {
            if (! $this->isOnSale()) {
                return 0.0;
            }

            $percentage = (float) $this->sale_percentage;

            return $percentage > 0 ? min($percentage, 100.0) : 10.0;
        });
    }

    /**
     * Akciós nettó egységár egész forintra kerekítve; nem akciós terméknél null.
     */
    protected function salePrice(): Attribute
    {
        return Attribute::get(fn (): ?int => $this->isOnSale()
            ? (int) round((float) $this->net_selling_price * (1 - $this->effective_sale_percentage / 100))
            : null);
    }

    /**
     * A vevő által fizetendő nettó egységár: akciós terméknél az akciós ár.
     */
    protected function unitPrice(): Attribute
    {
        return Attribute::get(fn (): float => (float) ($this->sale_price ?? $this->net_selling_price));
    }
```
